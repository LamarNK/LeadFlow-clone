# CRM: аналитика на одной странице, три блока

Дата проверки: 09.09.2026. Основа: `25f5b71`, ветка `codex/crm-analytics-production`.
Изменения подготовлены локально. Продакшен, данные карточек и права пользователей не изменялись.

## Правила для руководителей

Один фильтр офиса, сотрудника и дат применяется ко всей странице, но основания показателей различаются.

1. **Результаты за период** — действия за выбранные даты по всем карточкам, включая старые. Новые лиды выделены отдельным показателем поступления и не являются ограничителем остальных чисел.
2. **Переходы по этапам** — фактические события «откуда → куда», в порядке этапов конкретного офиса; затем результаты сотрудников. Это не последовательная конверсионная воронка. Текущая нагрузка/задачи и качество телефонных разговоров сохранены в сворачиваемых разделах, с отдельными подписями дат.
3. **Конверсия новых лидов** — карточки, поступившие в выбранные даты, и результаты этой же группы до конца выбранного периода. Каждый результат делится на число поступивших карточек, а не на предыдущую ступень. При пустой базе процент не рассчитывается.

Пример: поступило 50 карточек, по ним было 3 первых контакта, ещё 17 контактов — по старым НДЗ. Общие дозвоны: **20**, конверсия новых лидов: **3/50 = 6%**.
Карточка поступила 01.09, закрыта успешно 20.09: успех относится к работе **20.09**, даже при нуле новых лидов в этот день. В конверсии диапазона 01–20.09 она также будет учтена; в конверсии диапазона 01–05.09 будущего успеха нет.

### Дозвон

Дозвон — первый подтверждённый контакт по истории CRM, не число SIP-звонков и не длительность разговора.

- Источники: `Лид`, варианты `НДЗ` (включая НДЗ 2, 73, 2.6, с подменным), `Недоступные подменные`, `Подменка`, важный лид/дополнительные входные этапы офиса.
- Назначение: `Переговоры`, `Переговоры долгосрок`, `Анкета`, либо закрытие с указанной причиной, кроме НДЗ.
- Причины не ограничены старым жёстким списком: например, «Исчез, слился» или собственная причина тоже подходят при допустимом исходном этапе.
- `Переговоры → Анкета` — анкета, но не второй дозвон. Возврат в НДЗ и повторный выход в переговоры не создаёт новый первый контакт.
- Прямой `Лид → Билет` сам по себе не включён в согласованный список дозвонов. Перевод в билет при этом учитывается.
- Сначала анализируется история карточки до конца периода, включая предыдущие даты/ответственных, затем применяется фильтр исполнителя. Иначе первый контакт мог бы повторно приписываться разным менеджерам.

### Единицы и атрибуция

- Анкеты, билеты, закрытия в первом блоке — **события**, повторные действия видны в детализации. Переходы во втором блоке тоже события.
- Конверсия — уникальные карточки внутри каждого результата. Одна карточка может присутствовать в нескольких результатах.
- Действие принадлежит исполнителю и офису события из истории, а не сегодняшнему ответственному/офису карточки. Исторические сотрудники остаются доступны в выборе и таблице.
- Новые лиды группируются по первому ответственному и офису поступления. «Выдано впервые» отдельно использует дату первого назначения, включая карточки, пришедшие раньше. Передачи коллегам/от коллег не смешиваются с первичной выдачей.
- Карточки, поступившие сразу в «Лид(Важный)», входят в «Новые лиды», базу конверсии и поступления первого ответственного наравне с обычными лидами. Без ответственного они входят в поступления офиса. Последующий перевод дальше или передача коллеге не убирает их из исходного поступления. Перевод старой карточки из «Лид» в «Лид(Важный)» новым поступлением не считается.
- Создание сразу в «Лид(Важный)» не рисует вымышленный переход из обычного лида. Названия и порядок офисной воронки не изменяются; удалённые этапы с событиями видны как исторические.
- Закрытие с причиной `Успех` — успех. `Контракт` остаётся отдельной причиной отказа согласно существующему справочнику CRM. Переход в этап с названием «Сделка успешна» без события успешного закрытия не подменяет успех.
- Повторное открытие не стирает состоявшееся закрытие из журнала действий. Повторные закрытия без записанного открытия отмечаются предупреждением.
- Даты: полуоткрытый UTC-интервал, рассчитанный из выбранных локальных календарных дат; начало включительно, следующий день после конца исключительно. Смена не является условием учёта действия.

## Прозрачность и доступ

Клик по показателю раскрывает карточки/события на той же странице, не сбрасывая фильтры. Детализация строится тем же расчётом, что число, с постраничной выдачей по 50 записей. Для конверсии показываются события-основания.
При передаче карточки за пределы текущего доступа результат сотрудника остаётся в числе, но недоступные карточки не раскрываются; выводится количество ограниченных записей. Проверки `CrmAnalytics`, `CrmBoard` и офисные ограничения сохранены.
Переключатель офиса сбрасывает только менеджера предыдущего офиса, сохраняя даты. Остальные страницы этим правилом не затронуты.

## Неполная история — не скрытые нули

- Если нет исходного этапа закрытия, используется предшествующая записанная история, но не сегодняшний этап карточки.
- Если исходный этап или причина всё равно неизвестны, закрытие остаётся в результате; дозвон не выдумывается. Есть предупреждение с детализацией.
- События без исполнителя остаются в общих итогах и отдельно отмечаются, но не назначаются текущему ответственному задним числом.
- Восстановленный исторический контекст и резервные поля поступления отмечаются.
- Ошибка API/загрузки показывается как ошибка, не как шесть нулей.

Новая логика не может восстановить события, которых физически нет в базе. Для доказательства полноты старых данных на продакшене нужна отдельная сверка истории и первичных документов/выгрузок. В рамках этой работы исторические данные не переписывались.

## Реализация

- `CrmSalesRules`: правила классификации и разбор переходов.
- `CrmAnalyticsSalesReport`: новый расчёт трёх блоков и источников детализации.
- `CrmSalesAnalyticsContracts`: явные единицы/основания для интерфейса.
- Старый многовкладочный интерфейс заменён; старый отдельный вычислитель дозвонов удалён. Базовые проверки доступа, сбор исторического состава сотрудников, нагрузка, качество звонков и доказательства переиспользованы. Старые поля DTO оставлены для совместимости; `Decomposition` строится проекцией нового расчёта.
- Кэш аналитики переведён на ключ `crm-analytics-v3-sales`.
- Идентификаторы групп детализации хэшируются: длинная причина или название этапа не ломает лимит URL-ключа.
- API и Web следует выпускать согласованно. Новая панель при старом API без `Sales` показывает несовместимость/ошибку, а не фиктивные нули. Миграций и изменений данных в этом патче нет.

Целевой прогон: **120 пройдено, 0 ошибок** (CrmAnalytics, PanelPermissions, LocalCalendarDateRange).
Использованы EF InMemory и SQLite; проверены 50 новых/3 новых контакта/17 старых, поздние закрытия, разные исполнители, переезды между офисами, первая выдача в другом офисе, отсутствие смен, исторические этапы, важный лид, алиасы, границы суток, повторные события, неполная история, отсутствие исполнителя, длинные причины, суммы менеджеров и пагинация 67 карточек.

Проверены основные раскрытия, переход в карточку, нулевая новая база при реальной работе, отсутствие смены, поздний успех, мобильная/десктопная ширина. Исправлено переполнение верхней панели.
