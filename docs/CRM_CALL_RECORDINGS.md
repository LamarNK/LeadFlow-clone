# Записи звонков

Раздел `/Crm/Recordings` расположен в левом меню CRM после «Пропущенные».
Доступ: роль `Admin` или `OfficeLead` и разрешение `crm-board` (включая
совместимые CRM-разрешения существующей политики). Для Manager, SeniorManager
и Operator раздел и прямые ссылки архива недоступны.

## Список и доступ

- Администратор выбирает офис стандартным переключателем либо смотрит все.
- Руководитель видит только свой текущий офис из `PanelUserProfiles`, а не
  произвольный офис из запроса или устаревшего cookie/JWT claim.
- Выключенные офисы и офисы с отключённой CRM исключаются.
- По умолчанию последние 7 календарных дней в часовом поясе браузера.
  Фильтры: даты включительно (максимум 366 дней), текущий ответственный,
  номер кандидата (от 3 цифр, полные российские номера 8/+7), направление.
- Страница содержит 30 записей. Сортировка: время звонка и ID по убыванию.
- Владелец существующей карточки является текущим ответственным; при
  неназначенной карточке не подставляется бывший сотрудник из звонка.
  Для звонка без карточки показывается связанный с ним сотрудник.
- Карточка, перенесённая в другой офис относительно звонка, исключается
  из архива вместе с аудио. Это не даёт старому офису доступ к чужой карточке.
- Звонок без карточки доступен в рамках своего офиса, без ссылки на кандидата.

## Аудио

Список берёт только звонки с заполненным `RecordingStoragePath`. Внешняя
ссылка провайдера без сохранённого файла не считается готовой записью.
Архив читается через существующий `CrmCallRecordingStorageService`; новые
копии в постоянном хранилище CRM не создаются. Настройка NFS/архива АТС
описана в `deploy/control-panel/RECORDINGS_STORAGE.md`.

API:

- `GET /api/v1/crm/calls/recordings` — метаданные и фильтры, без путей/секретных URL.
- `GET /api/v1/crm/calls/recordings/{callId}/content` — повторная проверка роли,
  офиса и доступности карточки на каждом запросе.

Web `/Crm/RecordingAudio?callId=…` отдаёт файл inline с поддержкой Range.
`&download=true` задаёт `Content-Disposition: attachment` с исходным именем.
Оба действия защищены; ответ аудио не кэшируется. Как и существующий плеер
карточки, Web использует временный файл на время HTTP-ответа и удаляет его
при закрытии потока. Это не второй постоянный архив.

Плееры используют `preload="none"`: открытие списка не скачивает все файлы.
При запуске одного остальные приостанавливаются; ошибка загрузки имеет
отдельное сообщение. Обработчики работают после быстрой навигации и фильтрации.
Скачивание не перехватывается навигацией CRM.

## Проверка и выпуск

Миграция БД не требуется. Для выпуска нужны согласованные версии API и Web;
перезапуск или изменение конфигурации Asterisk не нужны.

```sh
dotnet test Orbita.Tests/Orbita.Tests.csproj --filter 'FullyQualifiedName~CrmCallRecordings'
node --test Orbita.Tests/JavaScript/crm-recordings.test.cjs
```

Перед выпуском проверить обычным браузером: вход руководителя и администратора,
чужой офис/ID, прослушивание реальной записи, перемотку, скачивание, переход в
карточку, возврат через меню, фильтры и переключение офиса. Исходный endpoint
записи в карточке `/calls/{callId}/recording` сохраняет свою прежнюю модель доступа.
