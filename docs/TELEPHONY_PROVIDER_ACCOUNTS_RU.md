# Кабинеты Плюсофона и SIPOUT в Орбите

Орбита поддерживает несколько кабинетов одного провайдера в одном офисе. Каждый кабинет хранит собственные реквизиты, курсор синхронизации, webhook, номера и привязки сотрудников. Ошибка одного кабинета не перезапускает Asterisk и не влияет на SIP-регистрации других линий.

## Что попадает в Орбиту

- все входящие и исходящие звонки подключенного кабинета;
- звонки со всех номеров и SIP-аккаунтов внутри кабинета;
- дата, направление и длительность разговора;
- запись разговора, если запись включена у провайдера;
- сотрудник по его SIP ID или внутреннему номеру;
- карточка кандидата по номеру второй стороны разговора.

Ссылку на запись Орбита не оставляет единственным источником: файл копируется в закрытое хранилище Орбиты. Это важно для временных ссылок провайдеров.

## Подключение Плюсофона через интерфейс

1. В Орбите откройте **Настройки → Офисы → Телефония → Плюсофон**.
2. В блоке **Кабинеты Плюсофона** нажмите **Добавить кабинет**.
3. Укажите понятное название, `Client ID` и `Access Token` кабинета.
4. Поле собственных номеров можно оставить пустым. Оно не ограничивает загрузку звонков и нужно лишь как дополнительная подсказка при определении номера кандидата.
5. При необходимости выберите дату начала истории. Без даты Орбита заберет последние 7 дней, максимальная глубина — 180 дней.
6. Нажмите **Добавить кабинет**.

После сохранения синхронизация всего кабинета запускается автоматически. Дополнительные SIP-аккаунты и номера внутри того же кабинета отдельно добавлять не нужно.

Для практически мгновенного появления новых звонков можно дополнительно создать в Плюсофоне webhook завершения звонка:

1. Скопируйте показанный Орбитой URL.
2. В кабинете Плюсофона создайте webhook события `destroy` для всех звонков.
3. Вставьте URL целиком. Секрет уже включен в адрес. Если форма Плюсофона позволяет добавлять заголовки, вместо параметра URL можно использовать показанный заголовок `X-Orbita-Webhook-Secret`.
4. Включите запись входящих и исходящих разговоров в Плюсофоне.

Если webhook не настроен или временно не пришел, фоновая синхронизация все равно заберет звонок из API Плюсофона.

## Подключение SIPOUT через интерфейс

1. В Орбите откройте **Настройки → Офисы → Телефония → SIPOUT**.
2. В блоке **Кабинеты SIPOUT** нажмите **Добавить кабинет**.
3. Укажите название. Собственные номера можно не вводить, но для SIPOUT их рекомендуется указать, если в событиях не всегда корректно передаётся направление звонка.
4. Нажмите **Добавить кабинет** и сразу скопируйте показанный WebRequest URL. Секрет повторно не показывается.
5. В виртуальной АТС SIPOUT откройте общий сценарий, через который проходят звонки всех номеров кабинета.
6. В системном обработчике завершения `h` добавьте действие **WebRequest** и вставьте URL Орбиты целиком.
7. Если у кабинета несколько независимых сценариев, добавьте один и тот же URL в обработчик `h` каждого сценария.
8. Включите запись входящих и исходящих разговоров в SIPOUT и передачу `LAST_RECORDING_URL`.

SIPOUT отправляет Орбите завершенные звонки через WebRequest. Поэтому подключение создается в Орбите, но готовый URL нужно один раз вставить в интерфейсе SIPOUT. Серверные команды и перезапуск Asterisk для этого не нужны.

## Несколько кабинетов

Для второго и последующих кабинетов повторите добавление в том же разделе. Не объединяйте разные кабинеты в одну запись:

- у каждого кабинета свой `Client ID` и токен Плюсофона либо свой WebRequest SIPOUT;
- одинаковые ID звонков из разных кабинетов не конфликтуют;
- статус и ошибка отображаются отдельно;
- кабинет можно временно выключить, не затрагивая остальные кабинеты и SIP-линии.

Один кабинет сейчас относится к одному офису. Если один физический кабинет провайдера одновременно обслуживает несколько офисов, его следует подключить к офису-владельцу либо заранее разделить у провайдера; иначе номер кандидата может сопоставиться с карточкой не того офиса.

## Привязка сотрудников

В карточке подключенного кабинета выберите сотрудника и укажите его **SIP ID / внутренний номер**. Для Плюсофона это значение поля `account` из истории звонков; для SIPOUT — внутренний номер, который передается в `PREV_EXTEN`.

Привязка нужна для указания автора звонка. Сопоставление звонка с кандидатом выполняется отдельно — по номеру кандидата в карточке CRM или в его дополнительных телефонах.

## Как понять, что подключение работает

В карточке кабинета отображается один из статусов:

- **Синхронизируется** — реквизиты приняты, API отвечает;
- **Ожидает события** — SIPOUT ожидает первый WebRequest;
- **Подключается** — первый проход еще не завершен;
- **Ошибка доступа** — Плюсофон отклонил Client ID или токен;
- **Ошибка синхронизации** — временная ошибка API; текст причины показывается там же.

Затем откройте карточку кандидата, совершите тестовый разговор и дождитесь его завершения. В ленте должна появиться запись звонка с направлением, длительностью и кнопкой прослушивания. У Плюсофона первая синхронизация и появление записи могут занять несколько минут.

## Безопасность и обслуживание

- токены провайдера сохраняются в зашифрованном виде и не возвращаются в интерфейс;
- webhook-секрет показывается только при создании или перевыпуске;
- кнопка **Получить новый webhook** немедленно отключает старый адрес;
- записи скачиваются только по HTTPS с разрешенных доменов Плюсофона и SIPOUT;
- загрузка имеет ограничение размера и повторные попытки;
- подключение кабинетов не изменяет конфигурацию SIP-регистраций Asterisk.

## Диагностика на сервере

Обычное подключение выполняется через интерфейс. Команды ниже нужны только разработчику при диагностике.

```bash
cd /opt/orbita

docker compose -f docker-compose.images.yml --env-file .env \
  logs --since=15m api | grep -Ei 'telephony|plusofon|recording|archive'
```

Проверка кабинетов и последних звонков:

```bash
docker compose -f docker-compose.images.yml --env-file .env \
exec -T postgres psql -U orbita -d orbita -P pager=off <<'SQL'
SELECT "OfficeId", "Provider", "Name", "IsEnabled", "SyncStatus",
       "LastSyncedAtUtc", "SyncCursorUtc", "LastSyncError"
FROM "CrmTelephonyProviderAccounts"
ORDER BY "Provider", "Name";

SELECT c."StartedAtUtc", c."Provider", a."Name" AS "Кабинет",
       c."Direction", c."ClientPhoneNormalized", c."CardId",
       c."ManagerUserId", c."RecordingUrl" IS NOT NULL AS "Есть URL",
       c."RecordingStoragePath" IS NOT NULL AS "Файл сохранен"
FROM "CrmCalls" c
LEFT JOIN "CrmTelephonyProviderAccounts" a ON a."Id" = c."ProviderAccountId"
ORDER BY c."StartedAtUtc" DESC
LIMIT 50;
SQL
```
